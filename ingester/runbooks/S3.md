# Runbook S3: Write

Version 0.2, 10 September 2026.

## Purpose

Write the approved items into the engagement's records, deterministically, and record exactly what was written.

## Inputs

- The signed session sheet and the signed dossier.
- The engagement's records.
- The transcript file in `transcripts/unprocessed/`.

## Command

```
ingester/bin/stage <engagement> Tnnn S3
```

Or, as the skill: `/ingest-transcript Tnnn <engagement>` when the status is `needs-s3`.

## Outputs

- New rows in `registers/*.md`, ids from the next free number, citations in Source (Raised by for open items), Updated set to today.
- New elements and claims in `current-state-<domain>.md`, created from the template on the first write with the Domain from the session sheet.
- New rows in `topics.md`, and Episodes, Open items and Closed by extended on existing topics.
- Any accepted `STK.edit` items applied to `stakeholders.md`. The New stakeholders rows themselves were written when the sheet was signed (runbook S1); S3 writes them only if that step was skipped.
- The transcript register row completed: session date, title, attendees, domain, approvers and dates.
- `engagement.md` updated with the ingester and rules versions used.
- Every touched document's version bumped.
- `sessions/Tnnn/Tnnn.session-log.md`: one row per id created or changed.
- The dossier's `Target: new` lines are left as written; the session log maps item numbers to ids.
- The transcript file moved to `transcripts/processed/`, as the last step.
- A run log under `logs/`.

## Automatic checks

In order, and the stage refuses at the first failure:

1. The transcript is in `unprocessed/` and its SHA-256 matches the register.
2. Both files carry an Approver and an Approved on.
3. No pending verdict (F5).
4. No session log exists yet for this transcript.
5. `check-citations` passes on every accepted item.
6. `check-integrity --proposed` passes on the accepted set merged with the engagement.

If anything fails after the checks, the engagement is restored to its state before the write and the failure is reported.

## What the reviewer does

Nothing. Read the session log afterwards.

## What approval means

Not applicable. The signed files are the approval.

## On rejection

There is no rejection after the write. A wrong row is corrected by a later session or by a hand edit with Source noting the correction, never by rewriting history. A transcript is written once; a second S3 is refused because the file is in `processed/`.
