# Runbook S3: Write

Version 0.4, 12 September 2026.

## Purpose

Write the approved items into the engagement's records, deterministically, and record exactly what was written.

## Inputs

- The signed session sheet and the signed dossier.
- The engagement's records.
- The transcript file in `transcripts/unprocessed/`.

## Command

```
ingester/bin/stage <engagement> Tnnn S3
```

Or, as the skill: `/ingest-transcript Tnnn <engagement>` when the status is `needs-s3`.

## Outputs

- One new file per accepted item under `requirements/`, `decisions/`, `limitations/`, `risks/` and `open-items/`, ids from the next free four-digit number, citations under Source (Raised by for open items), `updated` set to today, an empty History section last.
- For an item that targets an existing id: every field in the block set as written (frontmatter fields in place, body sections such as Mitigation or Next action replaced, Links extended), the block's citations added under Source or Raised by, `updated` set, and one History line (F10) appended recording each field's old and new value with the transcript item and the citations. `item nn` references in any value resolve to the ids assigned in this run.
- New `systems/` and `processes/` files for new elements; new claims appended as `## fN` or `## sN` sections to their parent file. A claim that targets an existing section has its status and confidence set, the block's citations added to its evidence, and a history entry appended.
- New `topics/` files, and `episodes`, `open-items` and `closed-by` extended on existing topics, including the Resolution id of an open item closed in the episode.
- Accepted `STK.edit` items applied to `stakeholders/` files. The new stakeholder files themselves were written when the sheet was signed (runbook S1); S3 writes them only if that step was skipped.
- `transcripts/Tnnn.md` completed: session date, title, attendees, domain, the sheet approver and the dossier completion, with dates.
- `engagement.md` updated with the ingester and rules versions used.
- `sessions/Tnnn/Tnnn.session-log.md`: one row per id created or changed, and the marker `- S3 written on:`.
- `index/*.md` regenerated, including `changes.md`, one row per History line across the register.
- The transcript file moved to `transcripts/processed/`, as the last step.
- A run log under `logs/`.

## Automatic checks

In order, and the stage refuses at the first failure:

1. The transcript is in `unprocessed/` and its SHA-256 matches the register.
2. The session sheet carries an Approver and an Approved on, and the dossier carries a Completed by and a Completed on.
3. No pending verdict (F5).
4. No session log exists yet for this transcript.
5. `check-citations` passes on every accepted item.
6. `check-integrity --proposed` passes on the accepted set merged with the engagement. A mutation is overlaid on the row read from disk, so the rules see the item as it will read after the write; a mutation that targets a missing id, reopens a Closed open item or changes an Accepted decision to anything but Superseded fails here.

If anything fails after the checks, every item folder, the transcript file, `engagement.md` and the session log are restored to their state before the write and the failure is reported.

## What the reviewer does

Nothing. Read the session log afterwards.

## What approval means

Not applicable. The signed files are the approval.

## On rejection

There is no rejection after the write. A wrong row is corrected by a later session or by a hand edit with Source noting the correction, never by rewriting history. A transcript is written once; a second S3 is refused because the file is in `processed/`.
